## Purpose

Обеспечить воспроизводимое и безопасное развёртывание нового персонального агента либо перенос существующего агента из зашифрованной резервной копии без скрытых ручных операций.

## ADDED Requirements

### Requirement: Единая точка входа для setup

Система MUST предоставлять оператору отдельные режимы первичного развёртывания и восстановления, автоматически загружать проектный `.env` и завершаться с понятной ошибкой при отсутствующих командах, обязательных значениях, незаменённых `PLACEHOLDER` или недопустимых путях.

#### Scenario: Запуск с заполненным окружением
- **WHEN** оператор запускает режим `new` или `restore` из repository с корректно заполненным `.env` и установленными зависимостями
- **THEN** система использует значения из `.env` без ручного `source` или экспорта переменных

#### Scenario: Запуск с неполной конфигурацией
- **WHEN** `.env` отсутствует, содержит обязательную заглушку либо задаёт не абсолютный persistent-путь
- **THEN** система сообщает причину и не инициализирует или не восстанавливает restic repository и не запускает контейнеры; безопасная подготовка host и password file допускается до проверки backend-настроек restic

### Requirement: Безопасная подготовка host

Система MUST разрешать подготовку host пользователю root либо deployment-пользователю, чей UID совпадает с `OPENCLAW_UID`; при недоступных для записи родительских каталогах она MUST ограничивать повышение прав операцией подготовки каталогов. При подготовке от root persistent-каталоги и secrets MUST назначаться заданным `OPENCLAW_UID:OPENCLAW_GID`, а rootless-подготовка MUST создавать их от deployment-пользователя; существующая runtime-конфигурация MUST сохраняться без перезаписи.

#### Scenario: Подготовка deployment-пользователем
- **WHEN** текущий UID совпадает с `OPENCLAW_UID` и ближайшие существующие родительские каталоги доступны для записи
- **THEN** система создаёт state, workspace, auth-profile, backup и secrets без обязательного запуска всего setup от root

#### Scenario: Для каталогов требуется повышение прав
- **WHEN** текущий UID совпадает с `OPENCLAW_UID`, но host-каталоги нельзя создать с его текущими правами
- **THEN** система запрашивает `sudo` только для подготовки каталогов и продолжает повседневные операции от deployment-пользователя

#### Scenario: UID не соответствует конфигурации
- **WHEN** setup запущен не от root и текущий UID отличается от `OPENCLAW_UID`
- **THEN** система прекращает работу и объясняет необходимость использовать соответствующего deployment-пользователя либо root

#### Scenario: Runtime-конфигурация уже существует
- **WHEN** файл persistent `openclaw.json` уже присутствует
- **THEN** система сохраняет его без замены исходным шаблоном

### Requirement: Защищённое хранение master password restic

Система MUST вводить создаваемый или восстанавливаемый master password restic интерактивно без отображения, требовать совпадающее подтверждение и хранить пароль в обычном файле с mode `0600` внутри каталога с mode `0700`. `.env` MUST получать mode `0600`, а слишком широкий системный путь для каталога secrets MUST отклоняться.

#### Scenario: Новый пароль вводится безопасно
- **WHEN** режим `new` не находит файл master password restic
- **THEN** система дважды запрашивает непустой пароль без вывода на экран и записывает его с ограниченными правами доступа

#### Scenario: Восстановление использует сохранённый вне сервера пароль
- **WHEN** оператор запускает режим `restore`, даже если локальный password file уже существует
- **THEN** система повторно запрашивает и подтверждает существующий master password перед обращением к удалённому repository

#### Scenario: Интерактивный ввод невозможен
- **WHEN** пароль требуется создать или заменить, но setup запущен без интерактивного терминала
- **THEN** система завершает работу, не создавая пустой password file

#### Scenario: Каталог secrets небезопасно широк
- **WHEN** родитель `RESTIC_PASSWORD_FILE` совпадает с корнем файловой системы либо стандартным верхнеуровневым системным каталогом
- **THEN** система отклоняет конфигурацию до применения permissions или записи пароля

### Requirement: Первичное развёртывание нового экземпляра

Режим `new` MUST подготовить host, инициализировать новый зашифрованный restic repository, загрузить закреплённые OpenClaw images, запустить Gateway и выполнить штатную проверку здоровья. Режим MUST предотвращать случайное использование repository, уже содержащего snapshots персонального агента.

#### Scenario: Новый пустой repository
- **WHEN** оператор запускает `setup.sh new`, а удалённый restic repository ещё не инициализирован
- **THEN** система инициализирует repository, загружает закреплённые images, запускает Gateway и подтверждает успешный healthcheck

#### Scenario: Продолжение прерванного первичного setup
- **WHEN** repository уже инициализирован, но не содержит snapshots с тегом `personal-agent`
- **THEN** система не повторяет инициализацию и продолжает загрузку images и запуск нового экземпляра

#### Scenario: Repository содержит историю агента
- **WHEN** repository содержит хотя бы один snapshot с тегом `personal-agent`
- **THEN** режим `new` отказывается запускать экземпляр и направляет оператора к режиму `restore`

#### Scenario: Для new переданы лишние параметры
- **WHEN** оператор передаёт режиму `new` snapshot или иной дополнительный параметр
- **THEN** система завершает работу с ошибкой использования команды

### Requirement: Восстановление существующего экземпляра

Режим `restore` MUST проверить доступ к существующему restic repository и наличие snapshots с тегом `personal-agent`, загрузить закреплённые images и восстановить `latest` либо явно указанный snapshot через проверяемый offline-процесс. После успешного восстановления Gateway MUST оставаться остановленным.

#### Scenario: Восстановление последнего snapshot
- **WHEN** оператор запускает `setup.sh restore` без идентификатора snapshot и repository содержит snapshots агента
- **THEN** система восстанавливает `latest`, проверяет восстановленное состояние и сообщает, что Gateway не запущен

#### Scenario: Восстановление выбранного snapshot
- **WHEN** оператор передаёт существующий `SNAPSHOT_ID`
- **THEN** система восстанавливает указанный snapshot вместо `latest`

#### Scenario: В repository нет истории агента
- **WHEN** доступный repository не содержит snapshots с тегом `personal-agent`
- **THEN** система останавливает восстановление до замены live state

#### Scenario: Gateway уже запущен
- **WHEN** на целевой машине работает Gateway
- **THEN** система отказывается активировать восстановленное состояние до остановки Gateway

#### Scenario: Целевая машина содержит значимое состояние
- **WHEN** state, workspace или auth-profile содержат данные, отличные от исходного шаблона, и `--force` не передан третьим параметром
- **THEN** система прекращает восстановление и требует явного подтверждения `--force`

#### Scenario: Принудительная замена состояния
- **WHEN** оператор указывает snapshot и третий параметр `--force`
- **THEN** система перемещает предыдущее дерево в каталог `pre-restore-*`, активирует проверенное состояние и сохраняет Gateway остановленным

### Requirement: Безопасное переключение между машинами

После восстановления система MUST отделять восстановление данных от запуска Gateway и MUST явно требовать от оператора убедиться, что прежний экземпляр выключен, прежде чем запускать новый.

#### Scenario: Restore завершён успешно
- **WHEN** state успешно восстановлен и прошёл offline-проверку
- **THEN** система не запускает Gateway автоматически и выводит отдельную команду запуска после проверки старой машины

### Requirement: Просмотр доступных snapshots

Система MUST предоставлять проектную команду, которая сама загружает `.env` и выводит только snapshots с тегом `personal-agent`, включая эквивалентный Make target.

#### Scenario: Оператор запрашивает историю backup
- **WHEN** оператор запускает команду списка snapshots или `make backup-list`
- **THEN** система обращается к настроенному repository и показывает snapshots, отфильтрованные по тегу `personal-agent`

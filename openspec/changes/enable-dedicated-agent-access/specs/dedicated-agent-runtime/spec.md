## Purpose

Capability определяет автономную работу доверенного персонального агента на выделенной машине при сохранении контейнерной границы и управляемого переноса существующих установок.

## ADDED Requirements

### Requirement: Полный профиль инструментов
Система MUST по умолчанию предоставлять основному агенту и создаваемым им подагентам полный профиль доступных инструментов OpenClaw без глобальных запретов на runtime, файловые операции, cron, автоматизации, обмен между сессиями и управление Gateway.

#### Scenario: Выполнение команды из основной сессии
- **WHEN** доверенный пользователь просит агента выполнить shell-команду внутри его окружения
- **THEN** агент получает доступ к runtime-инструменту и может выполнить команду без участия оператора сервера

#### Scenario: Выполнение задачи в изолированной сессии
- **WHEN** основной агент делегирует подагенту задачу, требующую доступного runtime-инструмента
- **THEN** глобальная политика инструментов не блокирует runtime только из-за использования изолированной сессии

#### Scenario: Создание периодической задачи
- **WHEN** доверенный пользователь просит создать поддерживаемую OpenClaw периодическую задачу
- **THEN** агент может создать её через доступные инструменты cron или автоматизации без ручного запуска CLI оператором

### Requirement: Доступ к сохраняемому состоянию
Система MUST разрешать агенту читать и изменять доступные контейнеру рабочее пространство и persistent state, чтобы профиль, память, автоматизации и другие штатные runtime-данные сохранялись между перезапусками.

#### Scenario: Сохранение bootstrap-настроек
- **WHEN** агент завершает первичную настройку личности и пользователя
- **THEN** он может записать профиль и память в persistent state, и эти данные остаются после перезапуска контейнера

### Requirement: Изолированная граница хоста
Полный доступ агента MUST оставаться ограниченным контейнером и явно смонтированными каталогами. Развертывание MUST NOT предоставлять контейнеру privileged-режим, Docker socket, host network, root-пользователя или произвольный доступ ко всей файловой системе хоста.

#### Scenario: Проверка Docker Compose
- **WHEN** оператор разворачивает штатную конфигурацию проекта
- **THEN** агент видит только файловую систему контейнера и объявленные bind mounts и не может управлять Docker daemon хоста

### Requirement: Минимизация передаваемых секретов
Система MUST передавать контейнеру только переменные окружения, необходимые для работы OpenClaw, и MUST оставлять пароль restic и учётные данные удалённого backup backend на хосте. Документация MUST явно предупреждать, что необходимые OpenClaw-секреты доступны shell-процессам внутри доверенного контейнера.

#### Scenario: Учётные данные резервного копирования остаются на хосте
- **WHEN** контейнер агента запущен с полным профилем инструментов
- **THEN** его окружение не содержит `RESTIC_PASSWORD_FILE`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и другие host-only переменные только потому, что они заданы в проектном `.env`

#### Scenario: Необходимые секреты OpenClaw
- **WHEN** оператор читает инструкцию перед включением полного доступа
- **THEN** инструкция сообщает, что токены OpenRouter, Telegram и Gateway доступны процессу OpenClaw и могут быть прочитаны командами внутри контейнера

### Requirement: Миграция существующей установки одной командой
Проект MUST предоставлять одну идемпотентную команду, которая включает полный профиль в существующем persistent state, удаляет конфликтующие глобальные запреты, проверяет итоговую конфигурацию и применяет изменение без ручного редактирования JSON5.

#### Scenario: Переход с ограниченного профиля
- **WHEN** оператор запускает команду миграции для установки с профилем `minimal` и запретами runtime/cron
- **THEN** команда сохраняет остальные пользовательские настройки, включает полный профиль, убирает конфликтующие ограничения и перезапускает или иным штатным способом применяет конфигурацию

#### Scenario: Повторный запуск миграции
- **WHEN** оператор повторно запускает команду после успешной миграции
- **THEN** команда завершается успешно и не создаёт дубликатов, не сбрасывает профиль пользователя и не повреждает persistent state

### Requirement: Рекомендация выделенной машины
README MUST обозначать отдельную заменяемую машину без посторонних данных, пользовательских аккаунтов и сервисов как рекомендуемую среду для полного доступа агента. README MUST не рекомендовать эту конфигурацию для общей рабочей станции или сервера с чувствительными нагрузками.

#### Scenario: Выбор среды развертывания
- **WHEN** оператор знакомится с требованиями до установки
- **THEN** он видит рекомендацию использовать выделенную машину, ограничить SSH-доступ, не размещать рядом чувствительные данные и поддерживать внешние резервные копии

### Requirement: Восстановление после ошибочных действий агента
Документация MUST объяснять, что полный доступ допускает ошибочное или нежелательное изменение доступного состояния, и MUST указывать актуальный backup/restore-процесс как способ восстановления.

#### Scenario: Агент повредил persistent state
- **WHEN** агент удалил или некорректно изменил доступные ему runtime-данные
- **THEN** оператор может восстановить состояние из зашифрованной удалённой резервной копии по документированному штатному сценарию

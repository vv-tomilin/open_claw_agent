## Context

См. мотивацию в `proposal.md`. Сейчас шаблон `config/openclaw.json` использует профиль `minimal`, разрешает только выбранные группы и явно запрещает runtime, Gateway и cron. Из-за persistent-конфигурации простая замена шаблона не изменит уже развернутые экземпляры. Одновременно Compose передаёт сервисам весь `.env`, хотя затем отдельно перечисляет необходимые OpenClaw-переменные.

Контейнер уже запускается без root, с `no-new-privileges`, урезанными capabilities и ограниченным набором bind mounts. Каталог локальной подготовки backup доступен контейнеру для штатных команд создания и проверки архивов; удалённые restic-снимки и их учётные данные управляются host-скриптами.

## Goals / Non-Goals

**Goals:**

- дать доверенному агенту и его подагентам штатный полный набор OpenClaw-инструментов;
- сделать новую установку готовой к автономной работе сразу после setup;
- обновить существующую установку одной повторяемой командой без потери пользовательских настроек;
- сократить набор host-секретов, видимых из контейнера;
- сохранить Docker-контейнер как внешнюю границу доступа к выделенному серверу.

**Non-Goals:**

- защита от действий владельца, которому разрешён Telegram pairing;
- безопасное совместное размещение с посторонними или чувствительными workloads;
- сокрытие от агента токенов, необходимых самому процессу OpenClaw;
- предоставление агенту root, Docker socket, произвольных host mounts или управления сервером за пределами контейнера.

## Decisions

### 1. Использовать профиль `full` без глобального deny

В шаблоне инструментов будет задан `tools.profile: "full"`, а прежние `alsoAllow`, `fs.workspaceOnly` и глобальный `deny` будут удалены. Это соответствует ожидаемому поведению «без ручных подтверждений» и не создаёт скрытой разницы между основной и изолированной сессиями. Сохранять granular allowlist или профиль `coding` не будем: они снова потребуют сопровождения списка при появлении новых штатных инструментов и могут блокировать автоматизации.

### 2. Считать Docker внешней границей доверия

Полный профиль действует внутри OpenClaw, но Compose не получает дополнительных привилегий. Сохраняются non-root user официального image, `no-new-privileges`, сброшенные сетевые capabilities, обычная bridge-сеть и только существующие целевые bind mounts. Docker socket и корень хоста не монтируются. Это уменьшает последствия ошибки агента до контейнера и данных, которые проект намеренно сделал persistent.

### 3. Не использовать `env_file` для сервисов OpenClaw

Compose продолжит читать `.env` для подстановки значений, но блок `env_file` будет удалён. В `environment` останется явный allowlist переменных OpenClaw. Так R2-ключи, путь к паролю restic и параметры host-скриптов не попадут в окружение агента. Альтернатива с отдельным вторым env-файлом отвергнута как лишний ручной шаг и дополнительный источник рассинхронизации.

### 4. Мигрировать только секцию политики инструментов

Будет добавлен идемпотентный скрипт и Make-цель для существующих установок. Скрипт загрузит `.env`, проверит prerequisites, штатными командами конфигурации OpenClaw установит `tools.profile=full`, удалит конфликтующие ключи старой политики, проверит конфигурацию и применит её перезапуском Gateway. Он не будет заменять весь `openclaw.json`, поэтому identity, pairing, память, модели и пользовательские настройки сохранятся. Для новой установки полный профиль уже будет находиться в копируемом шаблоне.

### 5. Сделать риск явной частью инструкции

README и документы безопасности будут описывать проект как конфигурацию доверенного автономного агента для отдельной машины. До команды установки пользователь увидит, что prompt injection, ошибка модели или скомпрометированный paired-аккаунт могут привести к выполнению команд, изменению state, утечке OpenRouter/Telegram/Gateway-токенов и расходам. Компенсирующие меры: отдельная машина, единственный доверенный Telegram pairing, ограниченный SSH, отсутствие посторонних данных, ротация токенов и внешний restic backup.

## Risks / Trade-offs

- [Агент выполняет разрушительную команду внутри контейнера] → ограничить host mounts, сохранять зашифрованные удалённые snapshots и документировать восстановление.
- [Prompt injection получает доступ к инструментам] → использовать только доверенные каналы и источники, не размещать рядом секреты/данные, не требуемые OpenClaw, и допускать ротацию сервисных токенов.
- [Shell читает обязательные токены из окружения] → явно документировать остаточный риск; host-only restic/R2-секреты не передавать контейнеру.
- [Агент меняет или удаляет локальные backup-архивы в `/backup`] → считать удалённый restic repository источником восстановления и не предоставлять агенту его credentials.
- [Существующая установка сохраняет старый restrictive config] → предоставить отдельную миграционную команду и показать её в README рядом с инструкцией обновления.
- [Новый инструмент OpenClaw автоматически становится доступен через `full`] → принимать это как сознательный trade-off простоты; проверять release notes перед обновлением закреплённой версии.

## Migration Plan

1. До изменения выполнить штатный backup и убедиться, что snapshot доступен в удалённом repository.
2. Обновить проект и запустить команду миграции полного доступа.
3. Команда точечно обновляет секцию `tools`, проверяет конфигурацию и перезапускает Gateway.
4. Проверить health, выполнение безопасной shell-команды, запись тестового файла и создание/удаление тестовой cron-задачи.
5. При откате восстановить предыдущий snapshot либо вернуть ограниченную секцию `tools` и перезапустить Gateway; скомпрометированные сервисные токены ротировать.

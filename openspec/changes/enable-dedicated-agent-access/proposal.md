## Why

Текущая политика инструментов не позволяет агенту самостоятельно выполнять команды, изменять свои рабочие файлы и создавать периодические задачи. Для установки на специально выделенную под агента машину это приводит к лишним ручным действиям оператора и мешает ожидаемой автономной работе.

## What Changes

- Включить полный профиль инструментов OpenClaw, включая shell/runtime, файловые операции, автоматизации и cron, управление сессиями и доступные инструменты Gateway.
- Сохранить внешнюю границу безопасности контейнера: непривилегированный пользователь, отсутствие Docker socket, host network, privileged-режима и произвольных каталогов хоста.
- Не передавать контейнеру весь `.env`: явно прокидывать только переменные, необходимые самому OpenClaw, а учётные данные restic и Cloudflare R2 оставлять на хосте.
- Добавить идемпотентную команду миграции для уже развернутого persistent state, чтобы включение полного доступа не требовало ручного редактирования runtime-конфигурации.
- Обновить README и эксплуатационную документацию: рекомендовать отдельную заменяемую машину без посторонних данных и сервисов, описать остаточные риски полного доступа и требования к резервному копированию.
- **BREAKING**: модель безопасности меняется с ограниченного ассистента без shell/cron на доверенного автономного агента с возможностью выполнять команды и изменять доступное ему состояние.

## Capabilities

### New Capabilities

- `dedicated-agent-runtime`: Полный доступ агента к инструментам внутри изолированного контейнера, безопасная передача секретов, миграция существующей установки и обязательные рекомендации по выделенному серверу.

### Modified Capabilities

Нет. В `openspec/specs/` пока отсутствуют основные спецификации; новое поведение оформляется отдельной capability.

## Impact

Изменения затронут `config/openclaw.json`, `compose.yaml`, скрипты установки и миграции, `Makefile`, `README.md`, документы и политики безопасности, а также проверки конфигурации. Требуемые OpenClaw-секреты останутся доступны процессу агента, поэтому установка будет считаться безопасной только на отдельной доверенной машине с ограниченным SSH-доступом и актуальными резервными копиями.
